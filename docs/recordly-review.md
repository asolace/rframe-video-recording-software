# Recordly review and Frame roadmap

Reviewed 6 September 2026 against Recordly commit [`68bca43`](https://github.com/webadderallorg/Recordly/tree/68bca43f6a8c1842ab9acfab75cfad817f737cb4). Recordly findings below come from source inspection; its application was not built or executed. Frame findings come from the current local source. This is a capability and architecture comparison, with no comparative performance benchmarks.

Frame should keep its dark interface, locked video canvas, original source preservation, and record → automatic transcript → select words or time ranges → cut → export workflow. Timeline magnification helps precise editing without changing the video's framing. Reintroducing crop or aspect-ratio controls is outside this roadmap.

| Cursor effects and automatic focus zoom | Electron/native helpers collect cursor and click telemetry; zoom suggestions cluster explicit click events. Captured video alone does not supply the event data this algorithm uses. Reliable arbitrary-application tracking would need a native companion or a narrower capture integration. ## Prioritized implementation plan

1. **Precise editing controls — implemented and verified.** Keyboard editing and 1–8× timeline zoom/pan are complete, with the locked video canvas preserved. Validation passed: production build, 33 unit tests, section deletion/export and transcript editor regressions, plus real-video browser checks for playback, split, I/O range marking, deletion, text/transcript guards, focus return, save/reload, proportional zoom and mobile layout.
2. **Protect work and complete the transcript workflow.** Add debounced metadata autosave, followed by portable project backup/restore. Add SRT/VTT export using edited timeline timestamps; then offer optional captions in the rendered video. Test reordered/repeated clips, deleted words, undo and restoration into an empty browser database. Keep automatic transcription cancellation and retry behavior intact.
3. **Improve recording confidence.** Add the optional countdown and an explicit shared-audio availability indicator. Implement sequenced chunk checkpoints with quota/write error handling and an intentional recovery screen. Only advertise recovery once interrupted recordings reopen and decode correctly; successful finalization should atomically save the project before removing its draft.
4. **Add waveform and deliberate format choices.** Cache audio peaks without changing source audio. Introduce MP4 capability detection and a clear fallback before committing to a full WebCodecs exporter; evaluate short GIF export separately. Validate decoded video, duration, clip order, audio continuity and cancellation for each supported route.
5. **Consider separate-source recording as a larger feature.** Start with a storage/schema and synchronization design. Native cursor telemetry, automatic focus zoom, OS-level audio capture and native FFmpeg fallbacks belong to a separately scoped desktop architecture decision, rather than the current browser improvement batch.

## Reuse and licensing boundary

Recordly's repository declares AGPLv3. Its accompanying summary also states user-facing/repository attribution requirements for reused or derived Recordly code and restrictions on using its name/branding. See the pinned [license file and repository summary](https://github.com/webadderallorg/Recordly/blob/68bca43f6a8c1842ab9acfab75cfad817f737cb4/LICENSE.md#L1-L18).

This review uses original prose and proposes independently written Frame implementations; no Recordly code or assets were copied. Any future source or asset reuse should receive a separate license review. This document does not conclude that independently written Frame code must adopt AGPL merely because it offers similar functionality.
